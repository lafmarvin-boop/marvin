  (lecture des traces temporaires d'assistance de Max, ajouté hier) n'était protégé que par un

## 3. Analyse du code changé depuis le 2026-09-15

- **`_ai-core.js` / `ai-suggest.js`** : passage de `thinking:{type:'enabled',budget_tokens}` à
  `thinking:{type:'adaptive'}` + `output_config.effort` (`claude-opus-5` refusait l'ancienne forme).
  Purement fonctionnel, aucun paramètre utilisateur n'entre dans ces champs (valeurs fixes ou issues
  de variables d'environnement serveur).
- **`_trace.js`** (nouveau) : écrit des lignes de diagnostic dans `suggestions` (`payment_id:'TRACE'`)
  depuis du code serveur uniquement (`_ai-core.js`, `assist-sweep.js`), avec la clé de service
  Supabase — pas un endpoint appelable depuis le navigateur. Contenu limité à des identifiants de
  session tronqués (8 caractères), des statuts et des messages d'erreur techniques tronqués (120-180
  caractères) : pas de contenu de conversation, pas de donnée personnelle. `admin-stats.js:120`
  exclut bien ces lignes du tableau de bord (`payment_id=not.eq.TRACE`).
- **`assist-sweep.js`** : nouvelle reprise des sessions `status=eq.waiting` non assistées, avec
  affectation conditionnée à `status=eq.waiting` (si un écoutant a pris la session entre-temps, la
  mise à jour ne touche aucune ligne — pas de course gagnante possible côté attaquant, c'est une
  tâche planifiée interne). `s.id` passe par `encodeURIComponent`. Rien à corriger.
- **`chat-poll.js`** : nouveau calcul du délai de réponse de Max, dérivé de l'identifiant de
  message (pas d'entrée utilisateur libre). Aucune régression sur le contrôle d'accès existant
  (jeton visiteur/écoutant, inchangé dans ce diff).
- **`index.html`** : bascules son/vibration (localStorage, pas de donnée sensible), bulle de message
  provisoire posée en `textContent` (jamais `innerHTML`) — pas de nouveau point d'injection.
- **`blog.html` / nouvel article** : contenu statique, aucune donnée utilisateur.

Aucune régression ailleurs ; le seul point corrigible était le diagnostic listé en section 2.
